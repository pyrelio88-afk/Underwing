### 二、鹤伴是什么

**一句话介绍**：鹤伴是一个纯本地存储、零后端的居家照护卡片组与个人病历整理 Web 应用，帮没有医学和护理背景的患者与家属「查得到规范做法、看得懂背后原因、扶着老人时能听语音一步步跟做、遇到危险信号知道哪一步必须停下来联系医护」。

> 医疗边界声明：鹤伴仅提供健康教育与个人记录整理工具，不诊断疾病、不解读化验指标、不替代执业医护判断，所有演示数据均为虚构。

### 三、为什么做这件事

在调研居家照护场景时，我们梳理出四个真实存在的断层：

1. **信息要么太碎，要么太深**：家属着急查「低血糖怎么处理」「偏瘫怎么从床移到轮椅」「胰岛素笔打完停几秒」时，搜短视频节奏拖沓且缺乏权威出处，翻医学指南又满篇专业缩写，现场根本来不及消化。
2. **照护现场双手被占，常规网页看不清**：扶着长辈、手里拿着药瓶或敷料时，人很难凑到屏幕前阅读密密麻麻的小字；高龄配偶互相照护时，常规字号与低对比界面更容易看串行。
3. **突发状况下容易因慌乱做错致命动作**：比如糖尿病人低血糖已经叫不醒时强行喂糖水（会导致窒息），或者老人摔倒怀疑伤到头颈髋部时硬抱起来。家属最需要的是一眼能分清的「红线停手条件」。
4. **个人病历不敢随便传云端，复诊时又说不清病情**：出院小结、化验单里全是真实姓名、身份证号和住址，很多家庭顾虑隐私外泄；但平时记在纸片或聊天记录里的血压、血糖、症状又太零散，到了门诊短短几分钟很难向医生交代清楚。

### 四、怎么用（5 步上手，约 60 秒走完核心流程）

打开上方 Qoder Sites 公开链接后，无需注册登录，内置了一套带「虚构」标识的演示档案，按下面 5 步即可体验全部核心设计：

1. **翻一张照护卡，看「正面判断 + 背面原理」**  
   在首页「我的卡组」将鼠标移过「在家量血压」卡牌，感受柔和的纸质倾角与覆膜光泽；直接点击卡面（或点卡牌下方的「翻面看解释」），背面会展开每一条要求背后的医学原因（例如为什么袖带必须贴皮肤、为什么要静坐 5 分钟），点击右上角数字角标可直接跳到原始临床指南出处。
2. **点开「床旁伴读 · 大字跟做」，体验解放双手的中文语音向导**  
   点进任意操作卡（如「胰岛素笔怎么用」「吸入剂怎么用」或「床到轮椅转移」），点击顶部的「床旁伴读 · 大字跟做」。界面会切换为无干扰的超大字分步视图，一步一屏讲清动作与原因；点击「朗读本步」即可调用浏览器离线中文语音慢速播报，配以加高触控按钮同步记录步骤完成度。
3. **在「疾病照护图谱」按年龄与系统展开扇形子卡**  
   点击左侧导航「疾病照护图谱」（或顶部「卡片库 → 疾病照护图谱」），筛选「60+岁」，点开「脑卒中（居家康复期）」或「糖尿病」枢纽卡。画廊舞台会原位展开该病种的 5 条核心照护提示、年龄与性别注意事项，对应所需的测量卡、给药卡与安全卡会从枢纽身后扇形飞出，支持「一键加入本病照护卡」。
4. **查一次「突发状况 · 红线速查」**  
   点击侧栏或首页快捷入口的「突发状况 · 红线速查」，集中查看从各张临床指南卡中汇总出的危急停手信号（如血压高于 180/120 伴胸痛气短、低血糖意识不清、呼吸困难嘴唇发紫、伤口按压止不住血等）及「千万别做」禁忌，每条均可一键溯源至原卡。
5. **在「病历夹」切换多维趋势、打印「一页复诊单」或试一次本地脱敏**  
   进入「病历夹」，可在折线图上方切换「血压 / 指尖血糖 / 晨起体重」趋势，将鼠标移过、轻触或用键盘切换数据圆点即可在上方状态栏即时读取具体日期时间与数值；点击「一页复诊单」即可生成汇总了待问医生问题、在服药物、近期已确认体征与症状日记的 A4 打印页；点击「AI 帮我理一份 → 用一份虚构出院小结试试」，可查看本地自动抹除姓名、电话、身份证号后的纯文本预览，以及所有提取结果必须先进入「待核对」草稿、由家属逐条确认后才入库的安全机制。

### 五、技术向善（Hack4Good）的四条产品与工程底线

为了让医疗健康类作品经得起推敲，我们在开发全程设定了四条机器强制检查的底线：

#### 1. 零编造与诚实的证据分级
- 全站上线的 **15 张居家照护卡**（含 12 张临床测量/给药/安全/护理卡与 3 张通用整理工具卡）共关联 **51 份**真实权威来源，涵盖国家卫生健康委员会、中国疾控中心、中华医学会、北京市卫健委、香港卫生署长者健康服务，以及 WHO、英国 NHS、美国国立卫生研究院（NIH 下属 NIA / NHLBI / NEI）、MedlinePlus、美国心脏协会（AHA）等官方指南与患者指导。
- 我们把卡牌的「稀有度菱形标」改造成了**来源核验透明度指示器**：代码中按每张卡引用来源的核对状态自动计算等级——只有当该卡引用的全部指南均已完成原文通读核对（`v:"ok"`）时才允许点亮三颗菱形，否则自动降级公示。目前全库 **51 份来源已全部完成原文通读核对（51/51 `ok`）**，12 张临床卡全部达到三颗菱形（`◆◆◆ 来源全部核对`），3 张整理工具卡标为一颗菱形（`◆ 整理工具 · 不含临床建议`）。
- 在疾病扩展上，我们依据全球疾病负担研究（GBD）与 WHO 权威目录逐项筛查，绘制并逐张全分辨率人工核验了 **99 张**无五官中文标注信息图（WebP 压缩后共 2.64 MB），当前主动开放已过筛的 **86 个常见健康问题枢纽**（Tier 1 共 20 项、Tier 2 共 66 项），覆盖 5 个年龄段与 8 大系统；另有 2 项边界条目与 11 项窄范围条目在未经专科专家复核边界前主动克制、暂不列入推荐，且**全站绝不宣称诸如「覆盖 99% 疾病」的不实百分比**。

#### 2. 严守操作边界与「红色唯一性」铁规
- 用药类卡片（吸入器、胰岛素笔、滴眼液）严格只讲通用器具操作步骤与防污染/轮换要点，**全库零具体药名、零剂量数字建议**，由独立审查脚本通过正则表达式逐屏扫描拦截。
- 借鉴英国 NHS Care Cards 分级体系与警报疲劳研究，全站严格执行**红色唯一性**：无论在浅色模式还是深色模式下，红色像素只允许出现在「何时停下来联系医护 / 立即拨打急救电话」区块内，配备「红底描边 + 警示图标 + 可观察体征文字」三重编码，并放在操作按钮之前；删除记录、待核对状态、分类标签一律禁用红色，让红色真正保住救命信号的分量。

#### 3. 面向长辈、老视与眩晕敏感人群的无障碍细节
- 针对汉字字面率高的特点，正文默认采用 `18px` 字号、`1.75` 行高与零字距，数字统一启用等宽表格数字（`tabular-nums`），并提供「标准 / 大字」两档切换与高对比深色模式。
- 卡牌翻面遵循 W3C ARIA Disclosure 披露规范，使用真实 `<button>` 维护 `aria-expanded`，背面隐藏时自动附加 `inert` 属性移出键盘焦点序，避免读屏软件误读隐藏面。
- 当操作系统开启 `prefers-reduced-motion: reduce` 或用户在设置中打开「减弱动态效果」时，自动关闭 3D 指针倾斜、光泽追随与扇形位移动画，平滑降级为透明度切换。

#### 4. 纯本地优先（Local-First）与断网可用韧性
- 整套应用代码（根目录唯一构建产物 `index.html` + `assets/app.css` + `assets/app.js`）仅 **364.0 KB**，连同全部 115 张 WebP 插画（`2.87 MiB`）可部署站点总计仅 **3.23 MiB**（整个源码与资料仓库经去重压缩后也仅约 **4.44 MiB**），零第三方前端重框架、零远程字体阻塞、零后端数据库依赖。
- 血压、指尖血糖、晨起体重、服药打卡、症状日记与上传的病历原件默认全部保存在用户本机浏览器的 `localStorage` 与 `IndexedDB` 中，并提供 **JSON 全量备份一键导出与校验恢复**（带撤销恢复提示），防止移动端浏览器自动清理缓存导致长期记录丢失。

### 六、用 Qoder 开发、打磨与部署的过程复盘

本项目使用 Qoder 完成从模块化重构、去 AI 模板化界面精修、自动化质量门禁编写到 Qoder Sites 部署的完整闭环。核心协作分工如下：

1. **用我方制定的医学与设计约束文档驱动 Qoder 开发**  
   动手改代码前，我们先确立了两条硬约束交给 Qoder 严格执行：一是医学事实守恒（不准自由发挥任何未见于 `10-sources.js` 的临床建议，单句条目结构严防渲染出 `undefined`，条件 ID `hypo`［甲减］与照护卡 `hypo`［低血糖］严格隔离命名空间）；二是视觉去 AI 模板化（融合个人开源项目 Crane 的暖纸衬线编辑秩序与 Qoder 官网 `#F2F4F2` / `#255A41` 精确色彩令牌，杜绝紫蓝霓虹渐变与千篇一律的悬浮放大卡片）。
2. **攻克前端丝滑度细节（从机械跳变到物理阻尼与零重排搜索）**  
   在 Qoder 协助下，我们对交互手感做了三轮重点重构：
   - 将卡牌 3D 倾斜升级为 `requestAnimationFrame` 阻尼插值循环，离卡后平滑归零并自动停表释放 CPU，同时修复了 3D 翻转时子层 `translateZ` 未加背面消隐导致的文字镜像穿透问题；
   - 将卡片库搜索从全页重绘改为 `#libBody` 局部 DOM 刷新，并接入 `compositionstart` / `compositionend` 中文拼音输入法保护，连续输入中文拼音时焦点零闪烁；
   - 在视图切换、趋势图切换与疾病枢纽展开中加入基于 Web Animations API（`Element.animate`）的合成层微过渡，兼顾顺滑体感与同步 DOM 响应。
3. **编写四套自动化验证脚本逐屏把关**  
   为了不靠肉眼碰运气，我们在 Qoder 中构建并反复运行了四道自动化防线：
   - `build.py`：将模块化源码打包输出为标准静态目录，断言零占位符残留、校核全部 115 张 WebP 资源路径完整性；
   - `review.py`：驱动无头浏览器遍历桌面端、手机端、深色模式及全部卡牌详情视图，自动实测文字对比度（`≥4.5:1`）、触控命中高度、零控制台报错、剂量违禁词正则拦截以及亮暗双模式下的「红色唯一性」像素扫描；
   - `test_e2e.py`：端到端模拟卡组增删、翻牌无障碍属性、疾病图谱筛选展开、三类体征录入确认、一页复诊单生成、JSON 备份导入导出与本地脱敏全流程；
   - `budget.py`：持续监控静态代码与图片体积预算，确保公网加载轻快。
4. **通过 Qoder Sites 一键公开部署**  
   完成本地全量回归后，直接在 Qoder 会话中调用内置 Sites 能力将静态产物发布至 Qoder Sites，并在 `/sites` 面板确认为公开访问（Public），通过桌面与手机无痕模式完成线上回归验证。
