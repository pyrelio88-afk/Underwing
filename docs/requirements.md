# 鹤伴 Underwing — 用户全部要求（按时间整理，后者覆盖前者）

来源：上一个对话（2026-11-17 10:22–13:20 CST）+ 本项目 2026-11-17 13:34 指令。

## 产品定位（不变的底线）
- R1 让没有护理经验的患者/家属快速找到讲得清、看得懂的居家照护卡；需要时把个人记录按时间整理。
- R2 不诊断、不代替医生、不叫人擅自停药或改剂量；红色只留给「何时停下联系医护」。
- R3 每条临床信息可追到来源（权威指南/官方/论文），操作频率与个体差异不写成硬指令。
- R4 隐私：不放真实病历；浏览器不暴露 API Key；自动脱敏不承诺匿名；发云端前先给用户看、可编辑/取消，说明存储与删除。
- R5 演示数据必须明确标注虚构。

## 平台
- R6 电脑端优先，同时适配手机（窄屏单栏 + 底部导航）。

## 卡牌与内容
- R7 一张卡只讲一件事：适用情境、步骤图、易错点、何时停下联系医护、来源与更新时间。
- R8 卡面插画：画的是「人」在家做这件事（鹤只是吉祥物，只在标志/空状态）；风格=简笔画+适当淡彩，不要太华丽。
- R9 卡牌要「超级好看」：研究顶级卡牌（宝可梦/万智牌/炉石等）怎么做、有什么特点并落地；每张卡要有详细解释（为什么）。
- R10 适当 3D：卡牌倾斜/视差/反光；照护内容可 2D 也可 3D，自行判断；尊重「减弱动态效果」。
- R11 病变器官示意：对应病种可拖进度条看到器官随病程/控制不佳的变化，每档标来源、注明是示意。
- R12 病种覆盖「99%」常见病：可自行勾选、按病名搜索直接找到对应照护卡、一键加入「我的卡组」、列表没有的可自定义。覆盖率需拿权威清单对照报真实数字。
- R13 照护方法 + 一般给药方法（滴眼药、吸入剂、胰岛素笔、贴剂、栓剂、口服等）—只写操作不写剂量；必须深度联网查指南/论文，不能随便写。

## 病历夹
- R14 按人整理就诊/检查/用药时间线，日期、原始来源、「待核对」状态。
- R15 病历可上传（图片/PDF，存本机）。
- R16 AI 分析自动脱敏；AI 只出可对照原文的草稿，用户确认后才保存。

## UI
- R17 不要 AI 模板味、不要渐变卡片堆砌；参考 iOS 设计（组件、层级、大字、留白、触控）和别人的组件库，但不必照搬。
- R18 参考用户自己的 Crane（暖底、衬线标题、细线），但要彩色；之后要求深度参考 Qoder 官网 UI。
- R19 「架构都要优化」：代码与信息架构都要重构。
- R20 有创意。
