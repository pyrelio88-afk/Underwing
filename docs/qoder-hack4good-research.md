## 一、核心结论速览

1. **赛制结构决定「初筛首屏 60 秒」是胜负手**：大赛共设三大赛道，每个赛道初筛仅选出 **14 支队伍**（三赛道合计 42 支）进入线上直播路演决赛；而每赛道现金奖名额恰好也是 **14 席**（一等 2 + 二等 3 + 三等 4 + 优秀 5）。这意味着通过初筛即进入获奖圈，评委点开 Qoder Sites 公开链接后的前 60 秒直觉体验（是否秒开、是否切中真实社会痛点、交互是否顺滑、有无粗糙 AI 模板感）直接决定能否突围。
2. **评审核心导向重「真实场景闭环」轻「堆砌后端复杂度」**：官方公开导向聚焦四个问题——痛点真不真实、打开链接能不能直接用、产品完成度与交互巧思如何、Qoder 开发迭代过程是否清晰可信。鹤伴采用零后端静态架构，在 Qoder Sites 上天然具备首屏秒开、零冷启动报错、免注册即刻可试的优势。
3. **Hack4Good 赛道四维全中**：官方列举的技术向善典型场景包括「无障碍、教育与乡村、环保、医疗健康、老年人数字鸿沟、防灾应急」。鹤伴同时覆盖**医疗健康辅助**（51 份权威指南溯源的居家照护卡）、**老年人数字鸿沟与无障碍**（床旁大字跟做 + 离线中文语音伴读 + W3C 无障碍翻牌）、**居家突发应急分流**（红色唯一性警示与突发红线速查）以及**弱网/断网韧性与隐私保护**（纯本地存储 + 上传前脱敏确认）。
4. **去 AI 模板感靠「物理克制 + 纸感编辑排版」，不靠花哨炫技**：综合 `simeydotme/pokemon-cards-css`、`emilkowalski/skills`（及 `vaul` / `sonner`）、`raunofreiberg/interfaces`、`pyrelio88-afk/Crane`、`nhsuk/nhsuk-frontend` 与日本数字厅 `digital-go-jp` 设计系统的源码实践，真正消除 AI 模板味的关键在于：固定母版层级、1px 发丝边框与纸感留白、rAF 弹簧阻尼 3D 倾斜与低透明度柔光遮罩、高频输入零重排（拼音 IME 局部补丁）、低频视图切换使用可中断合成层动画，以及严格尊重 `prefers-reduced-motion`。

#### （2）Qoder Sites 静态部署技术规范与兼容性验证
根据 Qoder 官方文档检索结果，Qoder Sites 原生支持托管纯静态前端产物（HTML / CSS / JS / WebP），并提供三种发布入口：
- **会话自然语言发布（推荐，且最适合截图放进作品帖）**：在 Qoder 交互会话中直接输入「将项目根目录静态产物发布到 Qoder Sites 并设为公开访问」，由内置 `sites:sites-building` 与 `sites:sites-hosting` 自动完成打包上传。
- **可视化终端面板**：输入 `/sites` 打开 TUI 管理面板，查看部署状态并将访问策略切换为 **公开（Public）**。
- **命令行接口**：使用 `qoder sites list` / `qoder sites operations` 查看与管理站点。

**鹤伴针对 Qoder Sites 的架构适配优势**：
- **根目录单一权威构建产物与纯相对路径**：`python underwing/build.py` 直接将构建产物输出至仓库根目录唯一权威入口 `index.html` 与 `assets/`（移除了 `underwing/` 子目录内的重复构建副本与原始临时大文件，整个工作区总磁盘占用仅约 **4.44 MiB**）。`index.html` 通过相对路径引用 `assets/app.css`、`assets/app.js` 与 `assets/art/**/*.webp`，不使用 `type="module"`，无论挂载在 `*.qoder.website` 根域名还是子路径下均零跨域、零路径错误，同时保留双击本地 `index.html`（`file://`）离线直开能力。
- **URL Hash 深链路由（零服务端重写依赖）**：采用 `#/cards`、`#/library?tab=hubs&hub=04_diabetes`、`#/card/bp`、`#/folder?chart=glucose` 路由方案，评委刷新页面或分享深链不会触发静态托管常见的 404 错误。
- **极致首屏体积**：HTML + CSS + JS 合计约 **364.0 KB**（低于 400 KB 预算上限），115 张 WebP 插画（16 张照护卡 + 99 张疾病枢纽图）合计 **2.87 MiB**（整个可部署站点 `index.html` + `assets/` 共 **3.23 MiB**），且卡片配图启用 `loading="lazy" decoding="async"`，公网冷启动首屏仅加载当前视口所需几张卡片，移动端弱网亦可秒开。

## 三、GitHub 开源精品仓库前端工艺调研与转化处方

为彻底消除「AI 生成网页」常见的廉价渐变、千篇一律三栏卡片、僵硬悬停缩放与中文排版拥挤问题，本轮重点检索并拆解了 6 组代表性 GitHub 开源仓库的实现机制，结合项目既定的 14 份去 AI 化规范（见 `research_notes/deai-repo-study-20261117/report.md`），提炼出直接服务于鹤伴的工程处方。

### 3.1 `simeydotme/pokemon-cards-css`：弹簧阻尼 3D 卡牌物理与哑光可读性保护

- **仓库核心机制**：Simon Goellner 的宝可梦卡牌项目通过指针相对坐标归一化（`0–100%`），在 `Card.svelte` 中利用弹簧模型（`springInteractSettings = { stiffness: 0.066, damping: 0.25 }`）平滑驱动 `--rotate-x`、`--rotate-y`、`--pointer-x`、`--pointer-y` 变量，避免原生 `mousemove` 直接赋值带来的机械抖动与离卡瞬移回弹。
- **对鹤伴的工程转化（去花哨、保临床可读性）**：
  1. **原生 JS `rAF` 指数阻尼插值**：无需引入任何框架，在 `45-tcg.js` 中用 `requestAnimationFrame` 实现每帧约 `0.16` 系数的平滑追随（`curRx += (targetRx - curRx) * 0.16`），指针移出后平滑归零并在误差 `< 0.04deg` 时自动停止 `rAF` 循环，静止态 CPU 占用严格为 0。
  2. **倾角封顶与双面翻转合成**：宝可梦全闪卡可用 `±15deg`，但鹤伴正面承载带 5 个中文引线标签的方形护理信息图，倾角过大会导致远端汉字透视压缩难认。因此将倾角严格收敛在 `±6.5deg–8deg`，并与 W3C 披露式翻面角度合成（`rotateY((flipped ? 180 : 0) + curRy)`）；正反面子层统一加 `backface-visibility: hidden` 杜绝 3D 镜像字穿透。
  3. **柔光反光层（Matte-Foil Glare）**：弃用会烧白浅色底图的 `color-dodge` 彩虹镭射，改用极低透明度的单色径向柔光跟随指针，仅在 `r3`（来源全部核对）卡牌上呈现温润的铜版纸覆膜质感，确保 `#0F0D0C` 正文对比度始终大于 7:1。

### 3.2 `emilkowalski/skills` + `vaul` + `sonner` + `raunofreiberg/interfaces`：微交互物理与零卡顿法则

- **仓库核心机制**：
  - **频率门控（Frequency Gate）**：每天高频触发的操作（搜索打字、筛选切换、键盘快捷键）绝不加花哨进场动画；低频、具空间意义的动作（翻开卡片背面、展开疾病枢纽子卡扇面、呼出床旁伴读抽屉）才赋予精致动效。
  - **缓动与时长纪律**：进入与状态响应统一采用快速减速曲线 `cubic-bezier(0.23, 1, 0.32, 1)`（150–220ms），抽屉与扇形展开采用 `cubic-bezier(0.77, 0, 0.175, 1)`（≤380ms），**永不使用 `ease-in`**；按钮按压反馈固定为 `:active { transform: scale(0.96) }`，绝不对普通网格卡片使用 `hover:scale`。
  - **可中断性与比例缩放**：Rauno Freiberg 强调弹窗与浮层绝不能从 `scale(0)` 突兀炸出，而应从 `scale(0.98) + translateY(8px) + opacity: 0` 按比例轻柔浮现；Emil 的 `clip-path` 分段指示器与合成层 `transform/opacity` 过渡确保快速连点时随时从当前位置平滑重定向。
- **对鹤伴的工程转化**：
  1. **中文拼音输入法（IME）零中断搜索**：此前每次 `oninput` 全量重绘 `#app` 会销毁 `<input id="q">`，打断中文拼音组词。现改为监听 `compositionstart` / `compositionend` 并只局部刷新 `#libBody` 结果容器，输入框焦点与光标纹丝不动，同时保持编程触发 `input` 事件的同帧同步响应。
  2. **同步 DOM + 合成层 WAAPI（`Element.animate`）**：视图与图表切换先同步完成 DOM 写入（保证零延迟响应与自动化测试稳定），再在非减动效环境下附加 180ms 的合成层微位移淡入，完全规避 CSS `@keyframes` 对减动效审查的干扰。

### 3.3 `pyrelio88-afk/Crane` + Qoder 品牌令牌 + `nhsuk-frontend` + 日本数字厅 `digital-go-jp`：床旁纸感手册与医疗无障碍

- **四大参考源融合逻辑**：
  1. **`pyrelio88-afk/Crane`（用户自有仓库设计基因）**：继承暖纸阅读秩序、衬线大标题与无衬线正文的编辑感对比、1px 细线分割、两步「草稿→人工确认」核对卡以及带「撤销」出口的深色轻量 Toast；按用户明确指令去掉单调黑白与朱红主色，注入温和清晰的分类色（测量蓝、给药紫、记录青、安全琥珀、护理绿）。
  2. **Qoder 官方界面精确令牌锁定**：全局锁定 `--bg: #F2F4F2`、`--card: #FFFFFF`、`--line: #E6E6E6`、`--ink: #0F0D0C`、`--brand: #255A41`、`--brand-2: #80C776`，一屏最多一个深绿实心主按钮，其余降级为发丝描边或幽灵按钮。
  3. **`nhsuk/nhsuk-frontend`（英国 NHS 医疗组件库）**：采纳其经过大规模患者测试验证的 **Care Card 就医分级模式**——标题直接写出行动指令（「出现以下任一情况，停下手头操作，立即拨打急救电话」vs「尽快联系医生」），全站严格执行**红色唯一性铁规**（红色只允许出现在 `.stop` 等紧急停手就医区域，删除按钮、待核对徽章、分类标签一律禁用红色，彻底消除警报疲劳）。
  4. **`digital-go-jp/design-system-example-components-html`（日本数字厅无框架无障碍组件库）**：借鉴其零前端框架依赖、面向高龄社会的 WCAG 2.2 AA 实践——中文正文 `18px` 起步、行高 `1.75`、零正字距、数字统一 `font-variant-numeric: tabular-nums`、移动端触控目标 `≥44px`（床旁伴读主按钮 `≥48px`）、隐藏卡面加 `inert` 移出焦点序，并在 `prefers-reduced-motion: reduce` 或应用内「减弱动态」开启时完全关闭 3D 倾斜与飞出位移，降级为温和透明度切换。

## 五、评委 60 秒黄金体验动线与赛前交付检查门（Pre-Submission Gate）

### 5.1 写进天池帖「怎么用」的 5 步评委动线（控制在 60 秒内走完高光闭环）
1. **翻一张卡（10 秒）**：打开公开链接，在首页「我的卡组」将鼠标移过「在家量血压」体验柔和 3D 纸感倾角，直接点击卡面（或点下方「翻面看解释」）查看每步操作背后的医学原因与角标出处。
2. **开一次床旁语音伴读（15 秒）**：点进「胰岛素笔怎么用」或「床到轮椅转移」，点右上角「床旁伴读 · 大字跟做」，点击「朗读本步」体验解放双手的中文语音跟做与大按钮勾选。
3. **展一组疾病照护图谱（15 秒）**：切到「卡片库 → 疾病照护图谱」，筛选「60+岁」，点开「脑卒中（居家康复期）」或「糖尿病」，看 5 条信息图要点与所需操作子卡从身后扇形飞出，一键加入卡组。
4. **查一次突发红线（10 秒）**：点击侧栏或首页「突发状况 · 红线速查」，查看按危急程度分级的「立即打急救电话」与「千万别做」安全底线。
5. **出一张一页复诊单 & 试一次本地脱敏（10 秒）**：进入「病历夹」切换血压/血糖/体重趋势图并点按数据点查看实时读数条，点「一页复诊单」预览门诊打印页，或点「AI 帮我理一份 → 用一份虚构出院小结试试」体验本地脱敏与「待核对」两步确认机制。
